# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Самодельная прошивка-«ОС» (`watchos/`) для часов **LilyGo T-Watch-2020 V3**.
Железо: ESP32 (с PSRAM), дисплей **ST7789 240×240** (подсветка GPIO15), PMU **AXP202**,
RTC **PCF8563**, ёмкостный тач **FT6336**, акселерометр **BMA423**. Управление — тач + одна
боковая кнопка (это кнопка питания AXP202 PEK; **энкодера на этом железе нет**).
`twatch_hello/` — первый минимальный скетч-пример, не трогать без причины.

## Сборка / прошивка

Через `Makefile` в корне (обёртка над `arduino-cli`):

```bash
make            # = make flash (собрать + залить)
make build      # только собрать
make flash      # собрать + прошить (PORT определяется сам; переопределить: make flash PORT=/dev/cu.usbserial-XXXX)
make fs         # залить ТОЛЬКО watchos/data/ в SPIFFS (станции радио) без перепрошивки кода
make sprites    # пересобрать спрайты игры: sprites/N.png -> sprites.png + sprites_gen.h
make font       # пересобрать кириллический VLW-шрифт заметок: TTF -> watchos/notesfont.h
make monitor    # серийный монитор, 115200
make ports      # список плат
make clean      # очистить кэш arduino-cli + удалить build_time.h
```

Ключевые требования (иначе не соберётся / будет глючить):

- **ESP32-ядро ОБЯЗАТЕЛЬНО `esp32:esp32@2.0.17`, НЕ 3.x.** Библиотека `TTGO_TWatch_Library`
  (v1.4.2) не компилируется на ядре 3.x (использует удалённые `ledcSetup`/`ledcAttachPin`,
  встроенный TFT_eSPI старый). FQBN: `esp32:esp32:twatch`.
- **`TTGO_TWatch_Library`** лежит в `~/Documents/Arduino/libraries/` (скопирована из GitHub
  Xinyuan-LilyGO, самодостаточна: внутри свои TFT_eSPI, AXP20x, BMA423 и т.д.). Плата
  выбирается в `config.h`: `#define LILYGO_WATCH_2020_V3`.
- **Радио** требует библиотеку `ESP32-audioI2S-master@2.0.0` (3.x требуют ядро 3.x — не ставить).
  Аудио-модуль назван `sound.h/.cpp`, а НЕ `audio.*`: на регистронезависимой macOS-ФС
  `#include "Audio.h"` (библиотека) иначе цепляет локальный `audio.h`. Станции — `watchos/data/stations.txt`
  в SPIFFS, заливаются через `make fs` (esptool на скорости 460800; 921600 даёт corruption).
- **`build_time.h` генерируется при каждой сборке** (`make` делает это автоматически). В него
  пишется реальная UNIX-эпоха хоста; `hw.cpp` ставит из неё RTC при старте. Без этого время на
  часах будет неверным. RTC батарейный — выставив один раз точно, дальше идёт сам.
- **Спрайты игры — единый атлас.** Исходники: `watchos/src/programs/dungeon/sprites/N.png` (каждый
  спрайт отдельным файлом 16×16, имя = индекс; **ключ прозрачности — салатовый 0,255,0**). `make sprites`
  (→ `tools/gen_sprites.py`) собирает их в `sprites/sprites.png` (просмотр) и **`sprites_gen.h`**
  (`SPRITES[N][256]` RGB565, салатовый → ключ `0xF81F`). Индексы 0–99 — террейн (тайлсет, на них
  завязан автотайл стен/пол — не сдвигать!), 100+ — сущности (`SPR_PLAYER`/`SPR_MON_BASE`/`SPR_CHEST`/…).
  Рендер (`gamerender.cpp`, `combat.cpp`) рисует только из `SPRITES[]`. Правка спрайта: перерисовать
  `sprites/<idx>.png` → `make sprites` → `make flash`. На экране тайл 32px (ровно ×2 от 16 — без «гуляния»).

Прямые команды без Makefile — не использовать (забудешь сгенерировать `build_time.h`).

## Архитектура

**Всё — равноправная «программа» (`Program`).** Главный экран, список приложений и любое
приложение реализуют один интерфейс и переключаются ядром по стеку.

- `program.h` — `struct Program { name; onEnter(); onTick(); onEvent(e,x,y); drawIcon(g,cx,cy,r);
  nav; navCount; keepAwake(); }`. Все поля кроме `name`/`onEnter` опциональны (nullptr).
- `kernel.cpp` — стек программ: `kernelOpen(p)` (push), `kernelBack()` (pop, дно = главный экран),
  `kernelRedraw()` (перерисовать текущую без glitch), `kernelCurrent()`. При входе сам рисует
  glitch-переход + `onEnter` + навбар.
- `watchos.ino` — `setup()`/`loop()`: `inputPoll` → (навбар/back/`onEvent`) → `onTick` текущей
  программы → `powerTick`.
- Фреймворк (в корне `watchos/`): `hw` (обёртка над TTGOClass, RTC, батарея, часовые пояса),
  `input` (нормализация тача+кнопки в события), `navbar`, `statusbar`, `theme`, `power`, `apps`,
  `modal` (общий каркас всплывающих окон/меню: `modalBegin`/`modalPoll`/`modalPanel` — см.
  «Модальные окна» в `src/programs/README.md`; переиспользовать во всех программах, не дублировать
  цикл опроса/рамку).
- Приложения — в `watchos/src/programs/` (`prog_*.cpp/.h`).

### Добавление приложения

**Подробный гайд с готовым шаблоном: [`watchos/src/programs/README.md`](watchos/src/programs/README.md)**
(жизненный цикл, события ввода, нижние кнопки/навбар, `keepAwake`/энергосбережение, правила отрисовки).

Кратко:
1. Создать `watchos/src/programs/prog_myapp.{h,cpp}` с `const Program myAppProgram = {...};`.
2. В `apps.cpp`: `#include "src/programs/prog_myapp.h"` и добавить `&myAppProgram` в массив `appList`.

## Критичные нюансы (наступали на эти грабли)

### Система сборки (Arduino-специфика)
- Arduino компилирует файлы в корне скетча и **рекурсивно подпапку `src/`**. Поэтому программы
  лежат в `src/programs/`, а фреймворк — в корне. Заголовки фреймворка из `src/programs/`
  подключаются относительным путём `../../foo.h`; соседние — просто `"prog_x.h"`. `apps.cpp`
  (корень) подключает `"src/programs/prog_x.h"`.
- `config.h` подключается во всех модулях (тянет `LilyGoWatch.h`); это нормально.

### Шрифты и UI
- **Интерфейс только на английском.** Кириллица намеренно не используется (чтобы не тянуть
  шрифты). Встроенные шрифты TFT_eSPI: **font 1** (6×8 моноширинный, полный CP437 — для ASCII-арта,
  канва 40×30), **font 2** (16px), **font 4** (26px), **font 6/7** (48px; 7 — семисегментный,
  только цифры и двоеточие).
- **Исключение — текст заметок (Notes): единственное место с кириллицей.** Используется встроенный
  VLW-шрифт `watchos/notesfont.h` (генерируется `make font` → `tools/gen_font.py` из системного TTF;
  латиница + кириллица, ~18px). Грузится через `tft->loadFont(notesfont)` / `unloadFont()` — обёртки
  `textFontLoad()/textFontUnload()` в `textview.*`. Между load/unload `drawString`/`textWidth`
  рисуют этим шрифтом UTF-8 (`SMOOTH_FONT` + `decodeUTF8` встроенного TFT_eSPI); после unload — снова
  штатные font 1/2/4. **Метки UI остаются английскими** — кириллица только в контенте заметок.
  Прокрутка длинного текста — компонент `textview.*` (word-wrap + скроллбар справа). Распознавание
  речи в текст — серверный эндпоинт `/stt` (`aiTranscribe` в `aiclient.*`, рядом с `/talk`).
- **`TFT_eSprite` ненадёжно рисует font 1** (GLCD уходит мимо буфера спрайта). Поэтому спрайтовую
  анимацию с ASCII-текстом НЕ использовать. Анимация списка приложений сделана простым glitch-эффектом
  + прямой отрисовкой. Встроенный TFT_eSPI старый — `setViewport` отсутствует.

### Тема (`theme.h/.cpp`) — киберпанк
- Палитра Matrix green (`COL_GREEN`) + amber (`COL_AMBER`) на чёрном. `RGB565(r,g,b)` макрос.
- **Фон каждое приложение рисует себе само** — глобальных флагов фона НЕТ. `themeBackdrop()` —
  только заливка + угловые HUD-скобки. Сетку (`drawGrid()`) рисует лишь главный экран. Скан-линий нет.
- Остались тумблеры общесистемных эффектов: `FX_GLITCH` (переход между экранами, `glitchFlash()`),
  `FX_TYPEWRITER` (бут-сплеш, `typeOut()`).
- ASCII-иконки приложений — `drawAsciiArt(g, lines, n, cx, cy, color, size)`.

### Время (3 пояса из одного RTC)
- RTC хранит базовый пояс **MSK**. UTC/EST — смещения в минутах в `config.h`
  (`TZ_UTC_OFFSET_MIN=-180`, `TZ_EST_OFFSET_MIN=-480`). DST не учитывается.
- Главный экран обновляется **раз в минуту** (показывает HH:MM; обновление раз в секунду давало
  неприятное моргание). Цифры рисуются прозрачным текстом поверх восстановленной сетки.

### Ввод
- Кнопка: короткое = `EVT_CLICK` (войти/выбрать), долгое = `EVT_BACK` (ядро делает pop).
  Тач: верт. свайп = `EVT_UP/DOWN`, тап = `EVT_TAP` (с координатами). Нижний навбар (как в Android,
  до 3 кнопок, по умолчанию «Back») ловит тапы первым, до программы.

### Энергосбережение (`power.h/.cpp`)
- Light sleep при простое `SLEEP_IDLE_MS` (config.h). **Пробуждение ТОЛЬКО кнопкой** (GPIO35).
- **Главный фикс:** в `powerBegin()` отключить ВСЕ прерывания AXP кроме PEK
  (`enableIRQ(0xFFFFFFFFFFFFFFFFULL, false)` → enable PEK) + `pinMode(35, INPUT)`. Иначе прочие
  IRQ (заряд/VBUS/батарея) держат линию GPIO35 в LOW и будят из сна мгновенно.
- Тач/акселерометр как источники пробуждения НЕ используются (ложные срабатывания).
- **Во время light sleep UART засыпает** → Serial-лог пустой; на батарее USB вообще не подключён.
  Диагностику сна делать **экранной**, не через Serial.
- **Модель сна — бинарная.** По умолчанию: простой `SLEEP_IDLE_MS` → **полная остановка** (экран
  гаснет + CPU в light sleep), пробуждение только кнопкой. Приложение-исключение
  (`keepAwake()==true`: секундомер на ходу, радио) **вообще не даёт уснуть** — устройство остаётся
  полностью активным (экран включён, CPU работает). Промежуточного «экран выключен, а CPU крутится»
  состояния НЕТ (намеренно убрано — не хотим тратить энергию в фоне).
- `keepAwake()` опрашивается у текущей (foreground) программы; выход из приложения снимает
  удержание. Для ФОНОВОГО радио (играет, пока ходишь по другим экранам) этого мало — понадобится
  явный wake-lock + фоновая FreeRTOS-задача (отложено до приложения «радио»).
- `Program.onExit()` вызывается ядром при выходе (`kernelBack`) — для освобождения ресурсов (Wi-Fi).
