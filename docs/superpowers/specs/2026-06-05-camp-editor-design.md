# Редактор лагеря (camp.html) + слой декора — дизайн

Дата: 2026-06-05
Статус: утверждён к реализации

## Проблема

`tools/autotile/camp.html` — визуальный редактор лагеря (camp = безопасная комната-хаб
в игре watchos). Сейчас он:

- грузит отдельный устаревший `tileset.png`, а не настоящий игровой атлас `sprites.png`;
- рисует сущности (костёр/торговец/лестница) цветными квадратиками-маркерами, не спрайтами;
- экспортирует текст+JSON, который никуда не подключён — раскладку переносят в код руками;
- предлагает кисть «алтарь», хотя алтари из кампов убраны намеренно (фарм статов).

Камп в игре захардкожен в `campTile()` (`worldgen.cpp`) и возвращает один тип тайла на клетку;
декоративного слоя нет.

## Цель

Сделать «хороший редактор лагеря» с пиксель-в-пиксель спрайтами из `sprites.png`, добавить
декоративный слой пропсов (бочки/факелы/кости и т.п.) и замкнуть петлю: редактор экспортирует
готовый C-код, который вставляется в `worldgen.cpp`.

## Решения (зафиксированы с пользователем)

1. **Выход редактора** — генерация C-кода (таблицы для вставки в `worldgen.cpp`). Без
   data-driven рефакторинга и без SPIFFS.
2. **Декор** — отдельный слой пропсов поверх пола, с правкой рендера игры.
3. **Источник декора** — новые прозрачные пропс-спрайты (новые индексы в атласе), не смена
   варианта пола.
4. **Набор пропсов** — бочка, ящик, факел, костёр-огонёк, кустик, гриб, кости, череп.
5. **Загрузка спрайтов в редактор (вариант A)** — `make sprites` дополнительно генерирует
   `sprites_gen.js`; редактор грузит его обычным `<script src>` и строит спрайты,키руя `0xF81F`
   → прозрачность. Те же пиксели, что в игре; без локального сервера; открывается двойным кликом.

## Архитектура

### 1. Спрайты и генератор (`tools/gen_sprites.py`, `sprites/`)

Новые файлы `sprites/N.png` (16×16, фон-ключ — салатовый `0,255,0`):

| Индекс | Имя              | Назначение                                  |
|--------|------------------|---------------------------------------------|
| 113    | `SPR_CAMP`       | костёр — функциональный тайл `TILE_CAMP`     |
| 114    | `SPR_PROP_BARREL`| бочка (декор)                                |
| 115    | `SPR_PROP_CRATE` | ящик (декор)                                 |
| 116    | `SPR_PROP_TORCH` | факел (декор)                                |
| 117    | `SPR_PROP_BUSH`  | кустик (декор)                               |
| 118    | `SPR_PROP_SHROOM`| гриб (декор)                                 |
| 119    | `SPR_PROP_BONES` | кости (декор)                                |
| 120    | `SPR_PROP_SKULL` | череп (декор)                                |

`N` станет 121. Изменения в `gen_sprites.py`:
- расширить `NAMES` указанными именами (`#define SPR_*` сгенерируются автоматически);
- дополнительно записать `sprites_gen.js` рядом с `sprites_gen.h`:
  `const SPR_PX=16; const SPR_N=121; const SPRITES=[[...],...];` (те же RGB565, ключ `0xF81F`).

Пропсы рисую сам как 16×16 PNG в стиле существующего тайлсета (киберпанк-палитра, читаемые
силуэты, салатовый фон). `make sprites` пересобирает атлас + `.h` + `.js`.

### 2. Игра

**`worldgen.h`** — объявить `uint8_t campDecoAt(int32_t x, int32_t y);` (индекс пропса или 0).

**`worldgen.cpp`:**
- `campTile(lx, ly)` переписать на литеральную таблицу:
  `static const uint8_t CAMP_TILES[12][12] = {…}; return CAMP_TILES[ly][lx];`
  (коды = значения enum `TILE_*`). Тело — продукт экспорта редактора; дефолт эквивалентен
  текущей раскладке.
- Добавить `static const uint8_t CAMP_DECO[12][12] = {…};` (индекс спрайта пропса или 0).
- `campDecoAt(x,y)`: если `isCampChunk(fdiv(x,C), fdiv(y,C))` → `CAMP_DECO[ly][lx]`, иначе 0.

**`gamerender.cpp`** (`gameRenderMap`, ветка пола):
- после `blitTile(floor)` и до сущностей: `uint8_t d = campDecoAt(wx,wy); if (d) blitKeyedCentered(x,y,SPR_PX,SPRITES[d]);`
- `TILE_CAMP` теперь рисуется спрайтом: `blitKeyedCentered(x,y,SPR_PX,SPRITES[SPR_CAMP])`
  вместо `drawMarker(x,y,t)`. Ветку `drawMarker` для `TILE_CAMP` убрать (для `ALTAR`/`EVENT`
  маркеры остаются).
- Порядок слоёв: пол → декор → сущность (сундук/торговец/лестница/костёр) → монстр → игрок.

### 3. Редактор (`tools/autotile/camp.html`) — переписать

- Грузит `sprites_gen.js` (`<script src="../../watchos/src/programs/game/sprites_gen.js">`);
  строит из `SPRITES[idx]` оффскрин-канвасы 16×16 с `0xF81F` → прозрачность.
- Рендер сетки 12×12:
  - пол — хэш-вариант, формула как в игре (`floorAt`: `wx*0x9E3779B1 ^ wy*0x85EBCA6B`, `^=>>13`,
    `FLOORS[h%12]`, `FLOORS=[11,12,13,14,21,22,23,24,31,32,33,34]`);
  - стена — автотайл `wallCase` (уже совпадает с `wallTileAt` игры; индексы
    INNER 3/4/55/50, рёбра 1/41/10/15, внешние углы 0/5/40/45);
  - сущности и пропсы — настоящими спрайтами с прозрачностью.
- Две группы кистей:
  - **тип тайла**: пол, стена, дверь, костёр(save), торговец, лестница, сундук (без «алтаря»);
  - **декор**: палитра пропсов 114–120 + «стереть декор».
- Hover-рамка и инфо-строка (координаты/тип/декор/текущая кисть), рисование зажатой кнопкой.
- «сброс к дефолту» = текущая раскладка кампа + пара пропсов для примера.
- **Экспорт → C-код** (модалка, кнопка «копировать»): два блока для вставки в `worldgen.cpp`:
  ```c
  static const uint8_t CAMP_TILES[12][12] = { … };
  static const uint8_t CAMP_DECO[12][12]  = { … };
  ```
  Коды тайлов — именами enum (`TILE_FLOOR` и т.п.) для читаемости; декор — числовыми индексами
  с комментарием-легендой (имя пропса).

## Тестирование (ручное, прошивка под железо)

- `make sprites` отрабатывает без ошибок; в `sprites_gen.h` `SPR_N==121` и есть `SPR_CAMP`/`SPR_PROP_*`;
  создан `sprites_gen.js`.
- `make build` зелёный после правок `worldgen`/`gamerender`.
- `camp.html` открывается двойным кликом, показывает пол/стены/сущности/пропсы корректно
  (без зелёных квадратов), кисти и экспорт работают.
- Экспорт из редактора вставляется в `worldgen.cpp` и компилируется (`make build`).
- На устройстве: камп рисуется костром-спрайтом и пропсами; дефолтная раскладка совпадает
  с прежним поведением (двери/торговец/лестница на местах), монстров в кампе нет.

## За рамками (YAGNI)

- Несколько разных раскладок кампа (сейчас одна на все кампы) — не делаем.
- Анимация пропсов (мерцание факела) — не делаем.
- Data-driven камп из SPIFFS — не делаем.
- Декор вне кампов (в обычных комнатах) — не делаем.

## Затрагиваемые файлы

- `tools/gen_sprites.py` — `NAMES`, вывод `sprites_gen.js`.
- `watchos/src/programs/game/sprites/113..120.png` — новые пропсы (создать).
- `watchos/src/programs/game/sprites_gen.h`, `sprites.png`, `sprites_gen.js` — регенерация.
- `watchos/src/programs/game/worldgen.h` / `worldgen.cpp` — таблицы + `campDecoAt`.
- `watchos/src/programs/game/gamerender.cpp` — декор-слой + спрайт костра.
- `tools/autotile/camp.html` — переписать.
