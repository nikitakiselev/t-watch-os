# AI Assistant — веб-стенд (debug-клиент) — дизайн

Дата: 2026-06-04
Статус: одобрен к реализации
Связано: [2026-06-04-ai-assistant-design.md], фаза 1 (сервер)

## Зачем

Браузерная страница, повторяющая весь сценарий ассистента (микрофон → отправка →
ответ голосом), чтобы отладить сервер с реальными ключами Yandex **до** прошивки
часов — в идеальных условиях, без рисков железа/PDM/I2S. Стенд ходит ровно в тот же
серверный путь (`POST /talk` → URL → проигрывание), что и будущие часы.

## Ключевое решение

Страница шлёт **сырой LPCM 16 кГц/16 бит/моно** — тот же формат, что отправят часы.
Сервер при этом **не меняется** (эндпоинт `/talk` уже принимает сырые байты, путь STT
идентичен). Никакого серверного ветвления по формату входа.

## Реализация

### Сервер
- Новый роут `GET /` → отдаёт `server/static/index.html` (`FileResponse`, text/html).
- Существующие `/talk`, `/audio`, фоновая чистка — без изменений.
- Dockerfile уже делает `COPY . /app/server` → `static/` попадает в образ
  (в `.dockerignore` не исключён).

### Клиент (`server/static/index.html`, один файл)
- Захват: `navigator.mediaDevices.getUserMedia({audio:{channelCount:1,
  echoCancellation:true, noiseSuppression:true}})`.
- `const ctx = new AudioContext({sampleRate: 16000})` — браузер ресемплит микрофон
  к 16 кГц. `ScriptProcessorNode(4096,1,1)` копит Float32-сэмплы, пока кнопка зажата.
  Узел подключён к источнику и к `GainNode(gain=0) → destination` (чтобы
  `onaudioprocess` срабатывал без обратной связи в динамик).
- На отпускании: склеить Float32, перевести в Int16 (`s = max(-1,min(1,f))*0x7FFF`),
  получить `ArrayBuffer` → `fetch('/talk?session='+uuid, {method:'POST',
  body, headers:{'Content-Type':'application/octet-stream'}})`.
- Ответ: `204` → статус «не расслышал», вернуться в idle; `200 {url}` → проиграть
  `new Audio(url)`, по `ended` → idle.
- UUID сессии: `crypto.randomUUID()` один раз на загрузку (эфемерно, как на часах);
  кнопка «new session» сбрасывает UUID.
- UI: крупная кнопка hold-to-talk (Pointer Events — мышь и тач), индикатор состояния
  `idle → recording → uploading → processing → speaking`, лог переписки (показываем
  свои отправки и URL/статус ответов; распознанный текст и ответ можно показать, если
  сервер их вернёт — но v1 сервер отдаёт только URL, поэтому лог технический).

### Состояния UI
`IDLE` → pointerdown → `RECORDING` → pointerup → `UPLOADING` (fetch идёт) →
(ответ) → `SPEAKING` (играет Audio) → `ended` → `IDLE`. Ошибка fetch/204/нет
микрофона → сообщение + `IDLE`.

## Тестирование
- Сервер: тест `GET /` → 200, `text/html`, тело содержит `/talk` (страница знает
  эндпоинт). Аудио-захват в браузере автотестами не покрываем (ручная проверка).
- Ручной сквозной прогон (с ключами Yandex): зажать → сказать фразу → услышать
  ответ; вторая фраза учитывает контекст первой (история сессии).

## НЕ в v1 (YAGNI)
AudioWorklet (ScriptProcessor проще и достаточно для debug), визуализация уровня/
осциллограф, отображение распознанного текста (сервер его не возвращает в v1),
выбор голоса/языка из UI.
